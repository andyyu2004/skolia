# Notes for Claude

- Open items and follow-ups go in git-bug (`git bug bug`, `git bug bug new --non-interactive -t … -m …`), as the current identity. Bugs are local refs: don't `git bug push` unless asked. A running `git bug webui` holds the lock; ask rather than stop it.
- Start each piece of work in a new git worktree, `~/dev/skolia-<name>` beside this checkout (`git worktree add ../skolia-<name> -b <branch> origin/main`), never in this checkout.
- main moves quickly. Fetch and branch from `origin/main`, and rebase before pushing more work onto an open PR.
- API tests call the typed client: `client(app, headers)` (src/testing/app.ts) with `body()` and `expectStatus()` (src/testing/responses.ts). `raw()` is only for requests the client can't express, such as malformed JSON. Don't call `app.request()` in tests; where you see one the client or `raw()` could make, rewrite it.
- Users have a `type`, `standard` or `system` (migration 0006). `system` is the e2e tests' importer (src/e2e-keys.ts), `curated` the curated texts' (src/sync-curated-key.ts). Each script replaces only its own API key id.
- Curated texts live in `curated/{lang}/*.yaml`, one text each, of a kind (api/src/curated-kinds.ts): `inline` has the text and its credits in the file, `wolnelektury` names a Wolne Lektury slug, fetched with its credits on each sync. Every deploy syncs them (`just sync-curated <env>`, src/sync-curated.ts). A push to main that only changes content (.github/changes.py) doesn't deploy; if it changes texts, CI syncs staging alone (sync-curated.yml), and production gets them at the next tag. An edited text, in the file or at its source, is a new document; the old one is deleted.
- Tags are kind:value pairs (`level:B1`) on a user's entry for a text, at most one of each kind, set and changed only by the entry's user and seen with the entry. The `tag` table (migration 0008) holds the ones that can be given, with a description and an order; a new tag is a row there, and `GET /api/tags` lists them, so the reader isn't written for any kind. `GET /api/documents?tag=level:A1&tag=level:B1` narrows the list: any of one kind, all of the kinds. Curated files give theirs under `tags:`; one the table lacks fails the sync, not the offline check.
- `@skolia/util/sql` (util/) is a tagged template for SQL put together from parts: values become parameters, `sql.join` and nested fragments bring their own. `@skolia/util/query` is an untyped query builder (`select`, `insertInto`, `update`, `deleteFrom`, `unionAll`, `eq`, `and`, `exists`, …) that compiles to a `Sql`, for queries put together conditionally: `where` skips false conditions and adds to those a query has. A string is a column where an expression goes and a parameter where a value goes; `col()` and `lit()` cross over, and `lit()` keeps a constant in the SQL for a partial index. A fixed query stays an `sql` template. `@skolia/util/checks` has the column checks the user Durable Object's migrations share (`iso`, `isoOrNull`).
- Put code that's needed in more than one place in a util package (util/, or shared/ for API and reader types) rather than copying it. A helper that a checksummed migration uses must keep making the same SQL.
- Avoid `string` where a narrower type exists. Ids are branded types from shared/schemas.ts (`DocumentId`, `UserId`, `CardId`, `LemmaId`, `Timestamp`), parsed where they come in (a route, a URL, a test's literal) and passed as that type from then on, in the API and the reader alike, query keys and props included. Statuses and kinds are unions of literals.
- A new timestamp column is named for its event with `_at` (`added_at`, `updated_at`), and its JSON field `addedAt`, `updatedAt`. Older columns (`updated`, `created`, `imported_at`) keep their names.
- Two different things are called `Ingester`: the Durable Object in api/src/worker/ingest.ts, which starts the container and hands it jobs, and the job loop in analysis/src/skolia_analysis/ingest/worker.py.
- The API binds the ingest Worker's `Ingester` (`INGESTER`, `script_name`) to ask where a document is in the queue. The workerd test harness has no ingest Worker, so src/testing/ingest-recorder is named `skolia-ingest` and has a stub `Ingester`.
- A PR that changes what the reader looks like has screenshots in its description, at desktop and phone widths (1280 and 390 px) where it matters. Run the reader against staging (`SKOLIA_API=https://staging.skolia.io pnpm --filter @skolia/reader dev`, where you're signed out), open a text by its link (lib/link.ts gives the word and view), and take them with Playwright: `uv run --with playwright python -I shot.py` from the scratchpad, with `playwright install chromium-headless-shell` once. Refer to them in the body as `![alt](./name.png)` and pass each file to `gh pr create` or `gh pr edit` as `--attach ./name.png`, which uploads it and rewrites the reference.
- TypeScript leans readonly and functional where it costs little: `readonly` fields and collections, values built with `map`/`flatMap`/`reduce` rather than filled in later, and objects whole when they're created rather than holding placeholders. A plain loop is fine when it reads better.
- api/src/bundle.test.ts caps the gzipped Worker bundle. CI's gzip came out about 1 KiB bigger than a local macOS build, so leave some room when raising it.
